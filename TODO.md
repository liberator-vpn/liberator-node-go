## Exit / GeoDNS optimization

Сейчас DNS резолвится на entry-ноде, а exit-нода выбирается по правилу/региону.
Это простая схема, но она не оптимальна для GeoDNS и CDN.

На будущее:

- каждая нода репортит свои публичные IP и регион;
- между нодами периодически замеряются пинги/задержки;
- результаты сохраняются в таблицу;
- для каждого клиента строится маршрут (Dijkstra) с учётом правил
  `direct`/`exit`/`deny`;
- на основе этого выбирается exit-нода и, при необходимости, GeoDNS-ответ;
- DNS-прокси и domain-правила при этом остаются, меняется только источник
  `exit_mesh_endpoint` и выбор оптимального пути.

Пока делаем простой вариант: DNS на entry-ноде, exit по текущему правилу.
